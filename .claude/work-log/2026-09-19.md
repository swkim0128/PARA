### 이번에 한 것

1. **래퍼 결함 수정** — `codex/instapaper-mcp.sh` SC2155. `set -euo pipefail` 아래에서 `export VAR="$(...)"` 는 종료코드가 `export` 에 가려져, Keychain 항목이 없어도 **빈 값으로 node 가 기동**됐다. 대입/선언을 분리하고, 항목이 없으면 사유 1줄 + 등록 명령을 stderr 에 내고 `exit 1`.
2. **배포** — `./install.sh personal` (기본 `INSTAPAPER_MCP_ENABLED=false`).
3. **실동작 테스트** — 더미 자격증명으로 MCP 본체를 stdio 로 띄워 JSON-RPC 핸드셰이크 실측.

### 발견 — 인증 실패해도 서버가 죽지 않는다

`build/index.js` 는 env 4개를 **존재 여부만** 검사한 뒤 기동 즉시 인증을 시도하는데,
실패해도 프로세스를 끝내지 않고 계속 서비스한다 (stderr 에 `Failed to authenticate: Unauthorized` 만 찍음).
→ API 승인 전에 `enabled = true` 를 켜면 **붙어는 있는데 전 호출이 실패하는** MCP 가 된다.
기본 비활성 배포가 옳다는 근거. 활성화 전 인증 확인 명령을 `docs/instapaper-mcp.md` 에 추가했다:
`~/.codex/instapaper-mcp.sh < /dev/null` (이 맥에는 `timeout`·`gtimeout` 이 없어 stdin 을 닫아 자기 종료시키는 형태로 확정).

### 남은 사용자 단계

1. Instapaper 개발자 API 승인 (https://www.instapaper.com/api) — consumer key·secret 발급
2. Keychain 4개 항목 등록 (`docs/instapaper-mcp.md` 의 `security add-generic-password` 4줄) — **현재 전부 미등록**
3. `~/.codex/instapaper-mcp.sh < /dev/null` 로 인증 확인
4. `INSTAPAPER_MCP_ENABLED=true ./install.sh personal` → Codex 재시작

### 확정한 사실 (1차 출처)

**Archify** — `tt-a1i/archify` MIT ★66.8k
- 스킬 실체는 레포 루트가 아니라 `archify/` 하위. **런타임 의존성 0**(devDependencies 뿐) → 순정 Node ≥18
- 기본 브랜치 = 개발판 `2.17.0-dev.1` / 안정 태그 = **`v2.16.0`(8/30)** → 벤더링은 태그 기준
- 흐름: `guide` → 스키마·예제 1개씩 → 후보 JSON → `validate --quality showcase`(9체크·0error·0warning) → `deliver`(SHA-256 영수증) → `visual-check`
- 외부 통신 = 업데이트 확인 1건. **`ARCHIFY_UPDATE_CHECK_DISABLED=1` 이면 즉시 silent**(`check-update.mjs:1637` 원문)
