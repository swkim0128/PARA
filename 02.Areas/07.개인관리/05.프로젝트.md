# 🗂️ 프로젝트 관리 SOP (툴 무관) — 저장소: 노션(어댑터)

> 공통 규약은 [README](README.md), 노션 전제 조건·절차는 [어댑터: 노션](adapters/notion/README.md), DB ID 는 [ids.md](adapters/notion/ids.md) 참조. 대상: Projects · Tasks · Sprint DB.

## 범위 경계 (중요)

Projects DB 는 **업무와 개인이 섞인 공용 DB** 다. 이 도메인은 **개인 프로젝트만** 다룬다.

| 구분 | 판정 | 취급 |
|---|---|---|
| `개인` 태그 (사이드 프로젝트·공부·정리·여행·약속·가계부) | 도메인 **범위 안** | 조회·생성·수정 대상 |
| `다나와` 태그 (요청업무·에러처리·리팩토링) | 도메인 **범위 밖** | 과거 경험정리용 아카이브 이력 — **읽기만, 수정 금지** |

> 업무 프로젝트는 경험정리 목적으로 과거에 기록한 것이고 **현재는 기록하지 않는다**(2026-08-17 확인). 신규 업무 항목을 이 DB에 만들지 않는다.

## 볼트 ↔ 노션 대응

`01.Projects/<프로젝트명>/` 폴더 1개 ↔ Projects DB 행 1개.

- **볼트** = 상세 설계·계획·진행내역 (`design.md`·`plan.md`·`requirements.md` 등)
- **노션** = 상태·우선순위·기간·태스크 관계의 인덱스
- 노션 페이지 본문에는 **볼트 노트 경로 + 재개 시 다음 행동**을 남긴다 — 노션만 봐도 이어받을 수 있게.
- 새 프로젝트는 **양쪽에 함께** 만든다. 한쪽만 있으면 동기화 누락으로 간주한다.

## 필드 규칙

| 필드 | 값 | 규칙 |
|---|---|---|
| Status | Planning / In progress / Paused / Backlog / Done / Canceled | 아래 추론표. **아카이브 판정 = `Status ∈ (Done, Canceled)`** — 별도 아카이브 플래그는 두지 않는다 |
| Priority | 낮음 / 중간 / 높음 / 긴급 | 미지정 시 `중간` |
| Tags | multi_select | **`개인` 접두 필수** + 세부 태그 1개 이상 |
| Area | relation | Areas DB(`collection://27dbfe89-…`) 연결. PARA 의 Area 대응은 이 relation 이 담당한다 |
| Start / End Date | ISO-8601 | 착수·종료 시 채운다. `Done`·`Canceled` 전환 시 End Date 필수 |

> 🗑️ **`ParaType` 속성은 2026-08-17 삭제됐다.** 옵션 4개 중 `Area`·`Resource` 는 Projects DB 에서 쓸 수 없어 사용 0건이었고, 남은 `Archive` 는 `Status` 종료 그룹과 93건 중 92건이 중복이었다. 근거·스냅샷 → `01.Projects/노션_루틴_업그레이드/paratype-removal-20260817.md`

**상태 자동 추론** — 완료·끝났어 → `Done` · 중단·잠깐 멈춰 → `Paused` · 다시 시작 → `In progress` · 취소 → `Canceled` · 아이디어·생각 중 → `Backlog` · 준비 중 → `Planning`

**Tasks**: Status `Not started / In progress / Test / Done / Cancel / Archived` · Effort `Low / Medium / High`(복잡·대규모→High, 간단·작은→Low, 기본 Medium) · `Project` relation 필수 · `Sprint` relation 은 사용자 요청 시만.

## 절차

1. **조회** — Projects DB 를 범위 경계에 맞춰 필터(`다나와` 제외). 결과는 Status 별로 묶어 표로 요약.
2. **생성** — 볼트 `01.Projects/` 폴더와 노션 행을 함께 만든다. 필드 규칙의 5개 항목을 모두 채운다.
3. **상태 변경** — 검색 → 단일 결과면 채택, 다중이면 목록 제시 후 선택 요청. `Done` 전환 시 End Date 를 함께 넣는다.
4. **태스크 추가** — 상위 프로젝트 확인 후 Tasks DB 에 생성, `Project` relation 연결.
5. 결과 보고 (공통 템플릿)

## 상태 판정 규칙

- **추측 금지.** 완료 여부는 산출물로 확인한다 — 스크립트면 파일 존재·실행 가능 여부, 설정이면 실제 배선 여부. 근거가 없으면 상태를 바꾸지 말고 그대로 둔다.
- 볼트 노트의 체크리스트·`상태:` 헤더가 1차 근거다.
