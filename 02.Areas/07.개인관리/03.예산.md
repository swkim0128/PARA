# 💰 예산 관리 SOP (툴 무관) — 저장소: 노션(어댑터)

> 공통 규약은 [[README]], 노션 전제 조건·절차는 [어댑터: 노션](adapters/notion/README.md) 참조. 대상: 월간 예산 페이지 — **고정 ID 없음, 명명 규칙으로 동적 검색** ([ids](adapters/notion/ids.md) 참조).

## 3-DB 역할 (2026-08-09 확정 — 이 문서가 정본)

| DB | 역할 |
|---|---|
| **💳 거래내역** | **실제 거래를 저장하는 원장(SoT).** 뱅샐 import 로 채운다. 모든 수치의 출발점. |
| **🏦 Household Ledger** | **거래내역의 통계.** 월 단위 집계(relation + rollup + 수식)만 담당하고 자체 거래 데이터를 갖지 않는다. |
| **🧺 Ledger** | **위시리스트.** 사고 싶은 항목을 관리하다가, 실제로 구매하면 `매핑 거래` relation 으로 해당 거래내역에 연결한다. |

- **HL 수치가 이상하면 거래내역을 먼저 본다** — HL 은 파생 집계라 원인이 거기 있지 않다.
- **🧺 Ledger 는 지출을 직접 기록하는 곳이 아니다.** 구매 전 후보 목록이고, 구매 후에는 거래내역과 연결만 한다.
- Budge 페이지 구성은 이 역할을 따른다: `월별 통계`(HL) → `위시리스트`(Ledger) → `구매 완료`(Ledger 완료분) → `거래내역`(💳, 토글).

> ⚠️ 아래 **카테고리 7종·절차·본문 템플릿 절은 구버전**이다. 실제 거래내역은 `대분류` 21종 / `소분류` 30종 select 를 쓰고, 월간 페이지도 동적 검색이 아니라 HL DB 의 행이다. 전면 재작성 대기 중 — 수행 시 이 경고를 지울 것.

## 카테고리 (7종 확정 — 이 문서가 정본)

**식비 / 교통 / 문화 / 의료 / 공과금 / 의류·생활 / 기타** — 7종 고정. 스킬·템플릿·합계 표는 모두 이 7종을 사용한다 (6종 표기는 오기).

## 절차

1. 이번 달 계산 `YYYY-MM`
2. `notion-search` 키워드 순차 시도: `{YYYY-MM} 예산` → `Budget {YYYY-MM}` → `예산 {YYYY}년 {M}월` → `가계부`
   - 0건 → 자동 생성 (사용자 확인 후, 제목 `{YYYY-MM} 예산`)
3. `notion-fetch` 로 페이지 + 내부 DB(또는 Budget data source) 구조 확인
4. 입력 파싱: **금액·항목명(필수) / 카테고리(자동 추론) / 결제 수단(선택) / 날짜(기본 오늘)**
5. `notion-create-pages` 또는 `notion-update-data-source` 로 지출 row 추가
6. 합계 갱신(본문 테이블 또는 rollup) → 잔액·경고 안내 → 결과 보고

## 규칙

- 통화 기본 KRW, 출력은 천 단위 콤마.
- **중복 방지**: 같은 날·같은 항목·같은 금액이 24시간 내 존재하면 확인 후 진행.
- **다중 항목 자동 분리**: "점심 8천, 카페 5천, 책 2만" → 3개 entry.
- **조회 모드**: "보여줘/확인/얼마/잔액" → fetch만, update 금지.
- **예산 경고**: 카테고리 100% 초과 `🚨 카테고리 예산 초과` / 80% 도달 `⚠️ 예산 80% 도달` / 총액 100% `🚨 총 예산 초과`. 예산이 0원(미설정)이면 경고 생략.

- 표 컬럼: **품목 | 예상가 | 등록일 | 상태 | 매핑 지출** — 상태는 `대기` / `구매완료` / `대체됨` 3종.
- **월 이월**: 새 달 페이지 생성 시 전월 wish list의 미구매(`대기`) 항목을 새 페이지로 복사한다.

## 뱅크샐러드 import 파이프라인

Gmail 수신 → 파싱 → 검증 → 노션 업로드의 4단계. **① 다운로드만 사람 손이 필요하고 나머지는 도구가 처리한다.**

| 단계 | 하는 일 | 수단 |
|---|---|---|
| ① 수신·다운로드 | 뱅샐 앱에서 내보내기 요청 → 메일 첨부를 드롭 폴더에 저장 | Gmail 검색 `from:export-noreply@banksalad.com has:attachment` 로 최신 메일 확인 후 **첨부 저장은 수동** (Gmail MCP 에 첨부 다운로드 도구 없음) |
| ② 파싱 | xlsx → 지출 JSON | `notion-budget` 스킬의 `scripts/parse_banksalad.py` (인자 생략 시 드롭 폴더 최신 파일) |
| ③ 검증 | 건수·합계를 노션과 대조 | 파서 출력 vs 노션 `거래내역` 집계 |
| ④ 업로드 | 노션 `💳 거래내역` DB 기록 | Notion MCP · `dedup_key` 로 중복 skip |

**메일·파일 규격** (2026-08-09 실측)

- 발신 `export-noreply@banksalad.com` · 제목 `{이름}님의 뱅크샐러드 엑셀 내보내기 데이터 (YYYY-MM-DD HH:MM:SS)` · 첨부 xlsx 1개.
- **드롭 폴더**: `~/Documents/banksalad/` (고정 — git 추적 볼트 밖, 금융 데이터를 원격 push 대상에 두지 않음).
- xlsx 에는 **시트가 2개**다 — `뱅샐현황`(요약)·`가계부 내역`(거래). 파서는 헤더(날짜+금액)가 탐지되는 시트 중 행이 가장 많은 것을 고른다. *첫 시트를 무조건 읽으면 거래 0건이 된다.*
- `가계부 내역` 컬럼 10종: 날짜·시간·타입·대분류·소분류·내용·금액·화폐·결제수단·메모.

**판정 규칙** — 파서(`parse_banksalad.py`)와 이 문서는 항상 함께 갱신한다.

- **고정지출** = 소분류 ∈ {`서비스구독`, `보험`, `기부`, `통신비`, `월세`, `관리비`, `전기세`} → 노션 `고정` 체크박스.
- **예산외지출** = `메모`에 `#예산외지출` 태그 → 노션 `예산외` 체크박스. 🚨 **뱅샐 앱에서 예산외로 설정해도 export 에 실리지 않는다** — 반드시 메모에 태그를 직접 달아야 한다.
- **부호**: 지출·이체는 음수, 수입은 양수로 내려온다. 노션 차트에 부호 반전 옵션이 없으므로 **월별 지출 그래프는 🏦 Household Ledger 의 `총지출` 기준**으로 그린다.

**검증·중복 방지**

- **중복 방지 키 = 날짜+금액+가맹점**(`dedup_key`) — 이미 기록된 조합은 skip (재업로드 안전).
- `뱅샐현황` 시트에 **대분류별 월별 지출 집계표**가 들어 있다(이체 제외·양수). 업로드 후 카테고리 합계를 이 표와 대조해 검산한다.
- 기존 **대화 입력("오늘 N원 썼어") 병행 유지** — import 는 대화 입력을 대체하지 않는다.

## Wish List 매핑 / 대체 규칙

import(또는 기록) 시 각 지출을 wish list `대기` 항목과 품목명 유사도로 대조한다:

- **일치** → 해당 항목 상태 `구매완료` + 매핑 지출 열에 해당 지출 연결.
- **유사 품목 구매** → wish list 항목을 실구매 품목명으로 교체한 뒤 상태 `대체됨` 처리 + 지출 연결.
- **모호** → 후보를 제시하고 사용자 확인.

## 월말 정리 규칙

- 매월 말, 그 달의 **카테고리별 합계 · 예산 대비 증감 · wish list 소화율**(구매완료+대체됨 / 전체)을 요약 블록으로 해당 월 페이지 **컨텐트에 append** 한다.
- **합계는 지출 내역을 재집계해 검산**한다 — 본문 합계 표와 불일치하면 재집계 값을 정본으로 표를 갱신하고 불일치 사실을 보고.
