# 💰 예산 관리 SOP (툴 무관) — 저장소: 노션(어댑터)

> 공통 규약은 [[README]], 노션 전제 조건·절차는 [어댑터: 노션](adapters/notion/README.md) 참조. 대상: 월간 예산 페이지 — **고정 ID 없음, 명명 규칙으로 동적 검색** ([ids](adapters/notion/ids.md) 참조).

## 카테고리 (7종 확정 — 이 문서가 정본)

**식비 / 교통 / 문화 / 의료 / 공과금 / 의류·생활 / 기타** — 7종 고정. 스킬·템플릿·합계 표는 모두 이 7종을 사용한다 (6종 표기는 오기).

## 절차

1. 이번 달 계산 `YYYY-MM`
2. `notion-search` 키워드 순차 시도: `{YYYY-MM} 예산` → `Budget {YYYY-MM}` → `예산 {YYYY}년 {M}월` → `가계부`
   - 0건 → 자동 생성 (사용자 확인 후, 제목 `{YYYY-MM} 예산`)
3. `notion-fetch` 로 페이지 + 내부 DB(또는 Budget data source) 구조 확인
4. 입력 파싱: **금액·항목명(필수) / 카테고리(자동 추론) / 결제 수단(선택) / 날짜(기본 오늘)**
5. `notion-create-pages` 또는 `notion-update-data-source` 로 지출 row 추가
6. 합계 갱신(본문 테이블 또는 rollup) → 잔액·경고 안내 → 결과 보고

## 신규 페이지 본문 템플릿

```markdown
# {YYYY-MM} 예산

## 예산
- 총 예산: 0원
- 카테고리별:
  - 식비: 0원 / 교통: 0원 / 문화: 0원 / 의료: 0원 / 공과금: 0원 / 의류·생활: 0원 / 기타: 0원

## 카테고리별 합계
| 카테고리 | 사용 | 예산 | 잔액 |
|---|---:|---:|---:|

## 지출 내역
| 날짜 | 항목 | 금액 | 카테고리 | 결제 |
|---|---|---:|---|---|

## Wish List
| 품목 | 예상가 | 등록일 | 상태 | 매핑 지출 |
|---|---:|---|---|---|
```

## 금액 파싱 룰

`5,000원→5000` / `5천→5000` / `오만원→50000` / `3.5만→35000` / `3만5천→35000` / `￦5000→5000` / `-5000→환불·취소` / `$5→환율 확인`
한글 숫자: 일1·이2·삼3·사4·오5·육6·칠7·팔8·구9·십10·백100·천1000·만10000

## 규칙

- 통화 기본 KRW, 출력은 천 단위 콤마.
- **중복 방지**: 같은 날·같은 항목·같은 금액이 24시간 내 존재하면 확인 후 진행.
- **다중 항목 자동 분리**: "점심 8천, 카페 5천, 책 2만" → 3개 entry.
- **조회 모드**: "보여줘/확인/얼마/잔액" → fetch만, update 금지.
- **예산 경고**: 카테고리 100% 초과 `🚨 카테고리 예산 초과` / 80% 도달 `⚠️ 예산 80% 도달` / 총액 100% `🚨 총 예산 초과`. 예산이 0원(미설정)이면 경고 생략.

## Wish List 규칙

- 구입 예정이거나 원하는 품목은 월 예산 페이지의 `## Wish List` 표에 미리 등록한다.
- 표 컬럼: **품목 | 예상가 | 등록일 | 상태 | 매핑 지출** — 상태는 `대기` / `구매완료` / `대체됨` 3종.
- **월 이월**: 새 달 페이지 생성 시 전월 wish list의 미구매(`대기`) 항목을 새 페이지로 복사한다.

## 뱅크샐러드 import 규칙

- **드롭 폴더**: `~/Documents/banksalad/` (고정 — git 추적 볼트 밖, 금융 데이터를 원격 push 대상에 두지 않음). 폴더 내 최신 파일(xlsx/csv)을 파싱한다.
- 파싱 결과 → 지출 도메인 모델(날짜·금액·가맹점·카테고리) → 해당 월 페이지 지출 내역에 기록.
- **중복 방지 키 = 날짜+금액+가맹점** — 이미 기록된 조합은 skip (재업로드 안전).
- 기존 **대화 입력("오늘 N원 썼어") 병행 유지** — import 는 대화 입력을 대체하지 않는다.

## Wish List 매핑 / 대체 규칙

import(또는 기록) 시 각 지출을 wish list `대기` 항목과 품목명 유사도로 대조한다:

- **일치** → 해당 항목 상태 `구매완료` + 매핑 지출 열에 해당 지출 연결.
- **유사 품목 구매** → wish list 항목을 실구매 품목명으로 교체한 뒤 상태 `대체됨` 처리 + 지출 연결.
- **모호** → 후보를 제시하고 사용자 확인.

## 월말 정리 규칙

- 매월 말, 그 달의 **카테고리별 합계 · 예산 대비 증감 · wish list 소화율**(구매완료+대체됨 / 전체)을 요약 블록으로 해당 월 페이지 **컨텐트에 append** 한다.
- **합계는 지출 내역을 재집계해 검산**한다 — 본문 합계 표와 불일치하면 재집계 값을 정본으로 표를 갱신하고 불일치 사실을 보고.
