# 🍽️ 식단 관리 SOP (툴 무관) — 저장소: 노션(어댑터)

> 공통 규약은 [[README]], 노션 전제 조건·절차는 [어댑터: 노션](adapters/notion/README.md) 참조. 대상 DB: Diet / Ingredients / Foods — **ID는 [ids](adapters/notion/ids.md) 인용** (하드코딩 금지).

- 주간 페이지 제목: `[week XX] @YYYY/MM/DD → YYYY/MM/DD 식단` (검색: `week {WW} {YYYY} 식단`)
- **주간 페이지는 n8n이 자동 생성** — 부재 시 폴백 생성 규칙(아래) 적용.

## 재고 관리 (SoT)

- **재고의 단일 정본 = Ingredients 마스터 DB의 '보유 중' 상태 속성.**
- **구매** → 해당 식재료 '보유 중' 설정 / **소진("다 먹었어")** → '보유 중' 해제.
- 주간 Diet 페이지의 Ingredients relation은 **파생 뷰(참조용)** — 재고 판정 기준이 아니다. 주 전환 시 이월도 마스터 상태 기준.

## 요일×끼니 표 (식사 기록·계획)

- Diet 주간 페이지 본문에 표 1개: **행 = 점심 / 저녁, 열 = 일~토**.
- 셀 항목: 실적은 그대로, **예정(계획)은 `(예정)` 접미** — 수행 확인 시 접미 제거 ([[04.일정]]의 예정/완료 표기 규칙과 동일).

## 페이지 부재 시 폴백 생성

- n8n 이 이번 주 페이지를 만들지 못했으면 표준 템플릿으로 **직접 생성**한다:
  - 제목: `[week XX] @YYYY/MM/DD → YYYY/MM/DD 식단` (주차 계산은 ISO 8601, [ids](adapters/notion/ids.md) 명명 규칙 참조)
  - 본문: 요일×끼니 표 (행=점심/저녁, 열=일~토, 빈 셀)

## 절차

1. 이번 주 Diet 페이지 검색 (`week {WW} {YYYY} 식단`)
2. 입력 분류: **식재료 추가(구매) / 식재료 제거(소진) / 음식 기록(실적·예정)**
3. 각 항목 처리:
   - `notion-search` 로 Ingredients/Foods 마스터에서 검색 → 없으면 `notion-create-pages` 로 신규 생성 (태그 자동 부여)
   - **식재료**: 마스터 '보유 중' 상태를 먼저 갱신(SoT) → Diet 주간 페이지 relation은 파생 뷰로 동기화 (**기존 배열 유지 + append**)
   - **음식**: 요일×끼니 표의 해당 셀에 기록 (+ Foods relation append)
4. 결과 보고

## 규칙

- **식재료 제거(소진)**: 마스터 '보유 중' 해제 + Diet 페이지 relation에서 제거. 마스터 DB 항목 자체는 삭제하지 않는다.
- **음식 기록**: 끼니 미지정("먹었어")이면 저녁으로 간주.
- 동일 이름 항목 다수 → 가장 최근 생성 항목 사용. 이름 모호 → 짧게 확인.

## 태그 분류표

- **식재료(Ingredients)**: 야채 / 정육·계란 / 해산물 / 국·반찬·메인요리 / 면 / 소스류 / 오일 / 조미료 / 과일 / 우유·유제품 / 생수·음료·차
- **음식(Foods)**: 단백질(고기·생선·계란) / 빠른(간단·즉석) / 건강한(채소·저칼로리) / 무거운(기름·고칼로리) / 주말(손 많이 가는) / 양식 / 일식 / 특별한(외식·특별한 날)

## 출력 포맷

```
✅ [week XX] 식단 업데이트 완료
| 구분 | 항목 |
|---|---|
| 식재료 추가 (+N) | ... |
| 식재료 제거 (-N) | ... |
| 음식 기록 (+N) | ... |
```

신규 생성 항목은 이름 뒤 `(신규)` 표시.

## 분기

- **식재료 + 가격 동시 언급 → 양방향 필수 분기**: 식재료는 본 SOP, 가격은 [[03.예산]]으로 기록. 식단 요청으로 먼저 접수됐더라도 가격이 언급되면 반드시 예산 기록을 함께 수행한다 (지출 기록 누락 방지).
