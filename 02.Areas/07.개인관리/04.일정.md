# 🗓️ 일정 도메인 규칙 정본 (저장소 중립)

> 공통 규약은 [[README]], 노션 전제 조건·절차는 [어댑터: 노션](adapters/notion/README.md) 참조. 대상 DB: 일지 및 회고 — ID는 [ids](adapters/notion/ids.md) 인용.
> **이 문서는 일정 도메인 규칙(무엇을 어떤 구조·표기로 관리하는가)의 정본이다.**
> **노션 MCP 조작 절차(fetch/스냅샷/replace JSON 패턴 등)는 어댑터(스킬 `notion-weekly-schedule` 의 `slot-edit-protocol.md` 등) 소관이며 이 문서에 두지 않는다.** 저장소(노션)를 교체해도 이 문서의 규칙은 불변이다.

## 주간 일지 페이지 개념 구조

주간 단위 페이지 1장 = **Week List + Week Things** 두 섹션.

- **Week List** — 이번 주에 해야 하는 일·했던 일의 **목차**. **업무(WORK) / 개인(LIFE)** 으로 분류하고, 각 분류 아래 하위 카테고리로 항목을 체크리스트(`- [ ]`/`- [x]`)로 관리한다.
  - WORK 하위 카테고리 예: 협력사 / Billing / Other
  - LIFE 하위 카테고리 예: Sport / Housework / Side Project / Study / Other
  - 자동 분류 기준: 회의·미팅·업무·배포·코드리뷰 → WORK / 운동·스터디·카페·약속·가족 행사·개인 학습 → LIFE
- **Week Things** — **일~토 요일 × 시간 블럭** 매트릭스. 각 요일에 했던 일(실적)과 예정인 일(계획)을 해당 시간 블럭 슬롯에 기록한다. 예정 작업은 사후 기록만이 아니라 **미리 등록**한다.

## 시각 미상 항목 배치 규칙

- 시각을 알 수 없는 항목(종일 이벤트 포함)을 **LIFE1(이른 아침)에 임의 배치 금지**.
- 기본값: **저녁 슬롯에 보수적으로 배치** — 평일 LIFE2·LIFE3, 주말 LIFE5·LIFE6.
- 배치가 애매하면 사용자에게 확인한다.

## 예정 / 완료 표기 규칙

- **예정 항목**은 슬롯·표 셀에 기록할 때 항목 뒤에 **`(예정)` 접미**를 붙인다. 예: `` `LIFE2` 클라이밍 (예정)``
- **수행이 확인되면 `(예정)` 접미를 제거**한다 (항목 자체는 유지 — 실적으로 전환).
- 수행되지 않은 예정 항목은 접미를 유지한 채 남겨 회고 시 Problem 후보로 삼는다.
- 이 규칙은 식단 요일×끼니 표([[02.식단]])에도 동일하게 적용된다.

## 일요일 주간 회고 규칙

- **매주 일요일**, 그 주의 Week List·Week Things 기록을 바탕으로 **KPT(Keep·Problem·Try) 템플릿**으로 회고를 작성해 주간 일지 페이지 하단에 추가한다.
- 템플릿·작성 기준(권장 개수, 좋은 회고 예시)의 상세는 스킬 `notion-weekly-retrospective` (`references/kpt-template.md`) 참조. 핵심 구조:

```markdown
## 📝 주간 회고

### Keep (유지할 것) ✅
### Problem (개선할 것) ⚠️
### Try (시도할 것) 🎯
### 한 줄 소감
```

- 분석 기준: `[x]` 완료 항목 → Keep 후보 / `[ ]` 미완료·`(예정)` 잔존 항목 → Problem 후보 / Problem에서 도출된 구체적 액션 → Try. WORK·LIFE 균형 있게.
- 실행 형태는 반자동(권고형): 일요일 세션이면 주간 루틴(정리 → KPT 회고 → 차주 계획) 실행을 우선 권고한다.

## 캘린더 연동

- 일정관리는 **노션 MCP + 구글 캘린더 MCP** 병용이 목표(Google Calendar MCP 우선, 미가용 환경은 gws CLI 폴백).
- 캘린더 이벤트를 슬롯에 반영할 때도 본 문서의 시각표·시각 미상 배치·예정/완료 표기 규칙을 그대로 따른다. 슬롯 반영은 append 기본(기존 수동 입력 보존).
