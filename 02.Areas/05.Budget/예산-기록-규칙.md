# 예산 기록 규칙 (Notion Ledger DB 등록 기준)

> 이 파일은 **앞으로 모든 예산 기록 작업의 단일 진실의 원천(SoT)** 입니다. 매번 카드 명세서·뱅크샐러드 데이터를 노션에 옮길 때 이 규칙을 따릅니다.

## 1. 데이터 소스

- **입력**: 뱅크샐러드 엑셀 export (`가계부 내역` 시트)
- **출력**: 노션 `Ledger` DB (`collection://7391b842-ef1c-42c5-a7ca-d82068dbaccd`)
- **상위 페이지**: `🏦 Household Ledger` DB (`collection://17f03db9-14ee-4379-bd14-f47194444f87`) 월별 페이지 (`HL-XX`)에 relation으로 연결

## 2. 기록 대상 필터

- 엑셀 `타입` 컬럼 값이 **`지출`** 인 행만 기록한다.
- `이체` / `수입` / 기타 타입은 제외.

## 3. 필드 매핑

| 엑셀 컬럼 | 노션 Ledger 속성 | 변환 규칙 |
|---|---|---|
| `날짜` | `지출일` (date) | `date:지출일:start = YYYY-MM-DD`, `is_datetime=0` |
| `대분류` | `카테고리` (select) | 1:1 동일 명칭 매핑 (아래 매트릭스 참고) |
| `소분류` | `세부 카테고리` (multi_select) | 동일 명칭 존재 시만 매핑, 없으면 빈 값 |
| `내용` | `Name` (title) | `"YYYYMM [엑셀 내용]"` 형식 (예: `"202604 맛있는바다"`) |
| `금액` (음수) | `가격` (number, 원화) | `abs(금액)` |
| `타입` | — | 필터링용 (저장 안 함) |
| `화폐` | — | KRW 외 무시 (예외 케이스만 본문 메모) |
| `결제수단` | — | **폐기** (노션 스키마에 속성 없음) |
| `메모` | — | **폐기** (노션 스키마에 속성 없음) |
| `시간` | — | 폐기 |

### 3-1. `카테고리` 매핑 매트릭스

| 엑셀 대분류 | 노션 카테고리 |
|---|---|
| 식비 | 식비 |
| 주거통신 | 주거통신 |
| 생활용품 | 생활용품 |
| 문화여가 | 문화여가 |
| 금융 | 금융 |
| 교통 | 교통 |
| 의복미용 | 의복미용 |
| 경조선물 | 경조선물 |
| 미분류 | _(빈 값)_ |

> 노션 카테고리 enum 전체: `기타비용, 생활용품, 의복미용, 교육학습, 문화여가, 의료건강, 여행숙박, 식비, 교통, 금융, 주거통신, 경조선물`

### 3-2. `세부 카테고리` 매핑 (특이 케이스)

엑셀 `소분류` 값이 **노션 multi_select 옵션에 존재하면** 그 옵션으로 매핑. 없으면 **빈 값**으로 두고 스키마는 변경하지 않는다.

특이 매핑 / 빈 값 케이스:
- `🍪☕️` (이모지) → **빈 값** (이모지·특수문자 포함 소분류는 모두 빈 값)
- `전기세` → **빈 값** (노션엔 없음, 옵션 추가 안 함)
- `미분류` → **빈 값**

> 노션 세부 카테고리 enum (47개): 가구가전, 강의, 게임, 결제충전, 고정지출, 관리비, 기부, 대중교통, 도서, 마사지, 문구, 미용, 병원비, 보험, 사진, 생필품, 서비스구독, 선물, 세금, 세탁수선, 숙박비, 스포츠, 시외버스, 시험료, 식재료, 약국, 여행, 영화, 외식, 운동, 월세, 음악, 의류잡화, 의복, 이사, 이자, 점심, 중개비, 철도, 축의금/부의금, 취미, 카페, 택시비, 통신비, 항공권, 헤어미용, 회비, 휴대폰

### 3-3. 기본값 / 상태

- `실행` (status) = **`실행완료`** (모든 신규 변동지출 기록의 기본값; 이미 카드 결제 완료된 항목이므로)
- `정기 지출일` = 빈 값 (변동지출은 정기 일자 없음)

## 4. 정기 중복 제외 (마스터 트랜잭션 재사용 항목)

다음 패턴에 해당하는 엑셀 행은 **변동지출로 등록하지 않는다.** 이미 노션 `FixedExpenses` 14건의 마스터 트랜잭션이 매월 월별 페이지 relation에 자동 연결되어 있으므로 중복 합산을 피하기 위함.

### 4-1. 카테고리 단위 정기 제외

| 엑셀 대분류 | 처리 룰 |
|---|---|
| **식비** | 카테고리 **전체 제외** — 정기지출의 "식비 정기 한도(약 530,000원)"로 일괄 처리. **단, 월간 식비 합계가 한도를 초과하면 §4-3 룰 적용** |

### 4-2. 개별 패턴 정기 제외 (엑셀 `내용` 매칭)

| 엑셀 내용 패턴 | 의미 | 매월 추정 금액 |
|---|---|---|
| `003.월세` / `월세` | 월세 | 430,000원 |
| `SK통신료` | 휴대폰 | 47k~50k |
| `메리츠002` | 보험 | 변동 (68k~96k) |
| `롯손04013` / `롯데손해` | 보험 | 32,932원 |
| `(주)귀뚜라미에너지` / `관리비` | 아파트 관리비 | 변동 |
| `전정남` / `전기세` | 전기세 | 변동 |
| `갤럭시아_정기과금` | 정기 결제 | 10,000원 |
| `우주패스_SK pay` | 멤버십 | 4k~9k |
| `쿠팡(와우멤버십)` | 쿠팡 멤버십 | 7,890원 |
| `네이버플러스멤버십` | 네이버 멤버십 | 4,900원 |

| `홈케어` | 정기 서비스 | 990원 |
| `기부금_효성4` | 정기 기부 | 10,000원 |

### 4-3. 식비 한도 초과 처리

- 월간 식비 합계 ≤ 530,000원 → **별도 등록 없음**, 정기지출에 흡수.
- 월간 식비 합계 > 530,000원 → **초과분만** 단일 변동지출 트랜잭션으로 등록:
  - Name: `"YYYYMM 식비 초과"`
  - 카테고리: 식비
  - 세부 카테고리: 빈 값
  - 가격: 합계 - 530,000
  - 지출일: 해당 월 말일

## 5. 예산외(OutOfBudget) 판별 룰

생성된 Ledger 트랜잭션을 월별 페이지의 어느 relation에 연결할지 판별 기준:

### 5-1. 자동 판별 (확정 룰)

- 엑셀 `결제수단` 컬럼 값이 **`네이버페이 간편결제(포인트)`** 인 경우 → **OutOfBudgetExpenses** (예산외) relation에 연결.
- **이유**: 네이버페이 포인트 결제 = 적립 포인트 사용 = 실제 현금 소비가 아닌 특수 결제. 예산내 합산에서 제외.

### 5-2. 기본 판별

- 5-1에 해당하지 않는 모든 변동 트랜잭션 → `VariableExpenses` relation에 연결.

### 5-3. 모호 케이스

위 룰로 판단 불명확하거나 큰 일회성 결제 등 특이 케이스가 보이면 **자동 분류하지 말고 사용자에게 확인 요청** 후 분류 결정.

## 6. 월별 수입 입력

뱅크샐러드 export의 `뱅샐현황` 시트 → `2.현금흐름현황` 섹션에서 월별 수입 데이터를 추출하여 노션 `🏦 Household Ledger` 월별 페이지에 다음과 같이 매핑한다.

### 6-1. 입력 필드 매핑

| 뱅샐 항목 | 노션 속성 | 의미 |
|---|---|---|
| `급여` | `DepositPrice` (number) | 메인 수입 |
| `기타수입 + 더치페이 + 보험금 + 부수입` (합산) | `ExtraDepositPrice` (number) | 서브 수입 (4개 항목 단순 합) |
| _자동 계산_ | `AllDepositPrice` (formula) | 수입총계 (DepositPrice + ExtraDepositPrice) |

### 6-2. 입력 시점

- 매월 말일 또는 다음 달 초 뱅샐 export 시점 기준.
- 급여가 아직 미입금인 경우(예: 월 중순 export) → 해당 월 입력 **보류**, 다음 export 시 입력.

### 6-3. 본문 표기

월별 페이지 본문 `### 개요` 섹션 상단에 수입 총괄 추가:

```
수입 총계: NNN,NNN원
- 급여 (메인): MMM,MMM원
- 서브 (기타수입/더치페이/보험금/부수입): KKK,KKK원
```

## 7. 월별 페이지 본문 보완

해당 월의 모든 트랜잭션 등록 완료 후, 월별 페이지(`HL-XX`) 본문의 `### 카테고리별 지출결과` 섹션을 다음 형식으로 채운다:

```

```
