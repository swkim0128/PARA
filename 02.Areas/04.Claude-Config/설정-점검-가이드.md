## 설정은 두 층으로 갈라진다

레포(정본)와 머신(배포본) 두 층이고, 머신이 둘이라 상태가 넷이 된다. **자산마다 반영 방식이 달라서** 한쪽만 최신인 상황이 만들어진다.

| 자산 | 반영 방식 | 커밋만으로 반영되나 |
|---|---|---|
| `CLAUDE-*.md` | 심링크 | ✅ 즉시 |
| `hooks/*.sh` | 심링크 | ✅ 즉시 — **단, 훅을 호출하는 배선은 아래** |
| `settings.json` | 생성 (base + overlay 병합) | ❌ `install.sh` 필요 |
| `~/.agents/skills/` | 복사 | ❌ `install.sh` 필요 |
| `~/.claude.json` 의 `.mcpServers` | jq 병합 | ❌ `install.sh` 필요 |

## 🚨 가장 헷갈리는 지점

**훅 스크립트는 심링크라 항상 최신인데, 그 훅을 호출하는 배선은 `settings.json` 안에 있다.**

그래서 **"파일은 있는데 동작은 안 하는"** 상태가 만들어진다. 훅 디렉터리를 아무리 확인해도 정상으로 보이므로, 배선 여부는 반드시 `settings.json` 쪽에서 확인해야 한다.

## 점검 절차 (전부 읽기 전용)

> ✅ **2026-08-29부터 자동 경보가 있다.** SessionStart 훅 `config-drift-check.sh` 가 정본 병합 해시와 배포본 해시, 미배포 스킬 집합을 비교해 **어긋날 때만** 한 줄 경고한다(실측 91ms, 정상이면 무출력). 아래 절차는 경고가 떴을 때 원인을 좁히거나 수동으로 확인할 때 쓴다.

1. **레포가 최신인가**
   `git -C ~/Project/vibe-ai-config fetch origin` → `git -C ~/Project/vibe-ai-config rev-list --left-right --count origin/master...master` (`0 0` 이면 동기)
2. **배포본이 레포와 일치하나** — `jq -s` 로 `settings.base.json` + `settings.<env>.overlay.json` 병합 결과와 `~/.claude/settings.json` 의 `permissions.allow`·`deny`·`hooks` 를 비교
3. **훅이 실제로 배선됐나** — `jq '[.hooks|to_entries[]|.value[]|.hooks[]]|length' ~/.claude/settings.json`
4. **스킬이 배포됐나** — `ls -1 ~/.agents/skills/ | wc -l`
5. **머신 간 비교** — `diff status/personal.md status/work.md`
   두 파일의 **`파일 전체 해시`가 같으면 배포본이 동일하다.** 26개 항목을 일일이 대조할 필요가 없다.
   ⚠️ `status/work.md` 는 업무 컴에서 `./install.sh work` 를 한 번 돌려야 생성된다.

## 뒤처졌을 때

```
cd ~/Project/vibe-ai-config
./install.sh personal      # 업무 컴은 work
```

기존 `settings.json` 은 `~/.claude/settings.json.bak.<타임스탬프>` 로 백업된다.

**배포 명령은 이것 하나뿐이다.** 과거에 병행하던 `deploy-links.sh` 는 2026-08-29 에 `install.sh` 로 흡수·폐기됐다(`_unused/`). 다른 배포 스크립트를 찾지 말 것.
