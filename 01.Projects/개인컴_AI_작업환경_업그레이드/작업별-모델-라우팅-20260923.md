## 적용 설계

1. 명시적 사용자 모델 선택이 있으면 우선한다.
2. 사전 정의 작업은 매핑표로 바로 선택한다.
3. 명확한 요청은 로컬 규칙을 적용하고, 나머지는 사용 가능한 경우 Jev로 분류한다.
4. Jev 응답은 허용된 분류만 수용하고 실제 사용 가능한 모델·추론 강도에 연결한다.
5. Jev 미설정·실패·낮은 확신은 로컬 기본 모델로 처리한다.
6. 실행 전에 선택 근거와 모델을 출력하고 해당 값을 실행 인자로 전달한다.

기존 `vibe-ai-config`의 모델 프로필·사용량 라우팅을 확장한다. 기능 정본은 설정 저장소이며 이 노트는 진행 기록이다. Jev의 개인 전용 정책과 외부 전송 범위를 유지한다.

현재 CLI 실행 경로의 작업 시작 시 모델 선택과, 모든 채팅 입력을 수신해 `turn/start`에 자동 반영하는 클라이언트 통합은 적용 범위가 다르다. 이번 구현의 실제 지원 범위와 미구현 범위를 결과에 구분한다.

## 매 입력 자동 라우팅 — app-server 실측 (2026-09-23, Claude 인계 후)

`codex-cli 0.154.0` 기준 `codex app-server generate-json-schema --experimental` 산출 스키마와 실제 기동으로 확인했다. 아래 3건은 기존 기재를 정정한다.

- **정정 1 — 진행 중 턴의 모델 변경은 가능하다.** `turn/steer` 에 모델 override 가 없다는 기재는 맞지만, 별도 메서드 `turn/settings/update` 가 `model`·`effort` 를 받는다("Experimental settings changes for one running turn, not future turns"). 즉 "매 입력 자동 전환 불가" 의 근거가 아니다.
- **정정 2 — TUI 재작성이 필요 없다.** `codex --remote <ws://host:port | unix://PATH>` 옵션이 공식 TUI 를 외부 app-server 에 붙인다. 따라서 클라이언트를 새로 만드는 대신 **TUI 와 app-server 사이의 JSON-RPC 프록시**로 `turn/start` 만 가로채면 된다.
- **정정 3 — `turn/start` 의 모델 지정은 sticky 다.** 스키마 설명이 "Override the model for this turn **and subsequent turns**" 다. 한 번 지정하면 이후 턴까지 끌고 가므로, 라우터는 매 `turn/start` 에 값을 명시해야 의도한 분류가 유지된다.

추가 확인:

- `model/list` 실호출 성공 — 계정 기준 라이브 목록에서 `gpt-6-astra`(default)·`gpt-5.6-sol`·`gpt-5.6-terra`·`gpt-5.6-luna`·`gpt-5.5` 와 각 지원 effort 를 받았다. 현재 `resolve()` 가 `models_cache.json` 만 보고 남기는 `model_evidence: local-cache-not-live-auth-check` 를 이 경로로 해소할 수 있다.
- 전송 방식: stdio 와 `ws://127.0.0.1:PORT` 기동을 확인했다. `unix://` 는 ①경로가 `SUN_LEN` 보다 짧아야 하고 ②인자가 소켓 파일이 아니라 **디렉터리**다. 본 세션의 샌드박스 셸에서는 unix 바인드가 `Operation not permitted` 로 막혀 **미검증**이다.
- 현재 로컬에 app-server 데몬은 떠 있지 않다(`app-server-control.sock` 없음). 실행 중인 `app-server` 프로세스는 ChatGPT 데스크톱 앱 소유다.

### 제안 구조


### Jev 가용성 — 외부 차단 (2026-09-23)

### Jev 대기 확정 — 존치 판단 (2026-09-23)

사용자 재확인: 가입뿐 아니라 **typesafe.ai 로그인 자체가 안 된다.** 키 발급 경로가 닫혀 있어 Jev 는 무기한 사용 불가이며 재개 시점은 외부에 달려 있다.

판단: **Jev 코드를 제거하지 않고 휴면 상태로 존치한다.**

- `route-task.py` 는 키 부재 시 `jev-not-configured` 로 로컬 기본값에 안전 강등된다 — 존치해도 실행 경로에 영향이 없다.
- `--jev-summary` 는 명시했을 때만 동작하는 옵트인이라, 미설정 상태에서 부작용이 없다.
- 지우면 복구 시 재구현 비용이 생긴다. 남기는 비용은 사용되지 않는 함수 두 개뿐이다.
- 따라서 **로컬 규칙 분류가 정식 주 경로**이고 Jev 는 선택적 보강으로 내린다. 인터페이스(`select()` 의 분류자 주입)는 그대로다.

### 로컬 분류기 과매칭 결함 (2026-09-23)

규칙을 9건으로 넓힌 1차 결과가 **적대적 문구 10/10 오분류**였다. 규칙이 주제(명사)만 보고 요청된 행위(동사)를 보지 않아, 주제어를 스치기만 해도 끌려간다.

```
요약 기능 구현해줘            → routine (implement 이어야 함)
아키텍처 문서 오타 고쳐줘      → deep
코드 리뷰 체크리스트 만들어줘  → review
로그 기록 모듈 리팩터링해줘    → routine
summarize 함수에 테스트 추가해줘 → routine (predefined-command 오탐)
```

비용은 비대칭이다 — implement→routine 은 품질 손실, implement→deep 은 사용량 낭비다. 조치: ①`intent_rules` 앞에 **implement 동사 우선 가드**를 두고 ②첫 토큰 명령어 매칭을 `/`·`$` 로 시작할 때만 인정하도록 좁힌다. 적대적 케이스를 회귀 테스트에 포함시켜 규칙을 넓힐 때 다시 깨지지 않게 한다.

**교훈**: 분류기는 맞히는 문구가 아니라 **틀리게 끌려가는 문구**로 검증해야 한다. 참 양성만 모은 표본은 과매칭을 전혀 드러내지 못한다.

### app-server 실측 함정 (2026-09-23)

`codex app-server` 는 **stdin EOF 를 종료 신호로 받는다.** 요청 세 줄을 한 번에 쓰고 stdin 을 닫으면(`communicate`) `initialize` 응답만 내고 종료해 `model/list` 응답이 오지 않는다. stdin 을 열어둔 채 순차 write+flush 하고 stdout 을 스트리밍으로 읽어야 한다. 프록시 구현 시 그대로 걸릴 함정이다.

1. `--profile` > `--task` > `/`·`$` 로 시작하는 명령어 토큰
2. `intent_rules` 를 순회해 **첫 매치의 span** 을 잡는다
3. `implement_guard` 의 **모든** 매치를 순회해(`finditer`) **구간 밖 매치가 하나라도 있으면** `implement`
4. 없으면 규칙 결과, 규칙도 없으면 기본값 `implement`

핵심 개념은 한 줄이다 — **규칙이 자기 매치 안에 그 동사를 이미 셈에 넣었는가.** 셈에 넣었으면(`일지 작성해줘`) 규칙이 이기고, 규칙 밖에 따로 붙은 동사면(`요약 기능 구현해줘`) 실제 작업 요청이므로 가드가 이긴다. 둘이 공존하면(`메모 추가하고 로그인 폼 만들어줘`) 밖의 동사가 있으므로 `implement` 다.

감사 기록의 `reason` 이 `local-intent`·`local-implement-verb`·`local-fallback`·`predefined-command` 로 갈려서 왜 그 모델이 골렸는지 사후에 추적된다.

### 이 작업에서 배운 것 — 분류기 검증법

**분류기는 맞히는 문구가 아니라 틀리게 끌려가는 문구로 검증해야 한다.** 참 양성만 모은 표본은 과매칭을 전혀 드러내지 못한다. 그리고 과매칭을 막는 가드는 곧바로 반대 방향(과소매칭)을 만들기 때문에, **양방향을 한 테스트에 묶어야** 다음에 규칙을 넓힐 때 한쪽만 보고 고치는 사고를 막는다.

`test_guard_and_rules_arbitrate_by_match_span` 이 그 역할을 한다 — ①규칙 밖 동사 ②규칙 안 동사 ③둘 공존 세 갈래가 한자리에 있다. 규칙을 건드릴 사람은 이 테스트부터 볼 것.

미지원으로 남긴 구간: "규칙 밖 동사가 있지만 실제로는 사소한 곁다리"(예: `일지 쓰고 오타도 좀 고쳐줘`) 는 `implement` 로 간다. 품질 손실이 아니라 사용량 쪽 비용이라 의도적으로 이 방향을 택했다.
