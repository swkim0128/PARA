Jev — 정형 판단 모델 개념과 활용

조사일: 2026-09-19. 공식 문서 재확인 기준이며, 공급자 설명과 로컬 테스트 결과를 구분한다.

관련 계획: [[archify-jev-도입계획-20260919]]

1. 핵심 개념

Jev는 TypeSafe의 첫 System One 모델이다. 자연어를 이해하고, 개발자가 지정한 답의 범위 안에서 판단값과 확률을 반환한다. 입력은 자연어 문자열이나 JSON 객체·배열일 수 있으므로, 입력부터 모두 정형 데이터여야 하는 것은 아니다. 응답 작성·코드 생성·판단 근거의 자유서술은 담당하지 않는다. 공식 개념

따라서 “LLM 대신 정형화된 데이터를 구성해 작업한다”는 이해는 다음처럼 구체화하면 정확하다.

  • 개발자가 판단 대상과 질문·선택 기준을 구성한다.
  • Jev가 해당 정보를 평가해 정형 판단값을 반환한다.
  • 호출한 프로그램이 판단값에 따라 실제 작업을 실행한다.

Jev가 스스로 터미널 명령을 실행하거나 파일을 수정하는 에이전트라는 의미는 아니다. 공식 예제도 판단 결과를 코드의 조건문과 연결해 작업을 배정한다. 판단과 실행의 연결

2. 모델·API·SDK의 구분

  • Jev: 판단을 수행하는 원격 AI 모델.
  • TypeSafe API: 모델을 호출하는 서비스 인터페이스.
  • typesafe-sdk: Python 프로그램이 API를 호출하고 응답 객체를 다루게 하는 클라이언트 라이브러리.

이번에 로컬에 설치한 것은 SDK 0.7.0이다. 모델 가중치를 내려받아 오프라인으로 실행하도록 설치한 것이 아니다. 공식 SDK도 API 키를 설정한 뒤 TypeSafeClient.system_one()을 호출한다. 공식 Python SDK

3. 입력과 반환 유형

호출에는 state(판단할 정보), model(모델 선택), questions(질문 목록)를 전달한다. 질문에는 instructions와 답의 기준인 criteria를 지정한다. 문서·메시지와 필요한 맥락을 state에 포함하는 방식이다. State, Choice 요청 구조

유형 질문 예 반환 의미
Choice 신규 요청·질문·정보 공유 중 무엇인가? 선택지 하나, 각 선택지의 확률, confidence
Score 긴급도가 낮음·보통·높음 중 어디에 가까운가? 단계 번호의 확률 가중 평균, 단계별 확률, confidence
Noul 사용자가 환불을 요청했는가? 참이라고 판단할 확률 0~1

Choice는 최대 255개 선택지를 받는다. Score는 2~10개 단계의 설명을 받으며 결과가 정수일 필요는 없다. Noul은 별도 confidence 없이 noul 수치를 반환한다. 코드가 필요에 따라 임계값으로 불리언으로 바꾼다. Choice, Score, Noul

4. 예시: 개인 작업 메시지 분류

다음은 이해를 위한 자체 설계 예시이며 실제 모델 호출 결과가 아니다.

state: "주말까지 독서 기록 화면을 만들어 줘."
instructions: "메시지의 의도를 분류하라."
criteria:
  new_task: 새 작업을 요청함
  question: 답변이나 설명을 요청함
  information: 정보만 공유함
  other: 위 분류에 해당하지 않음

Jev가 반환할 수 있는 선택값의 예: new_task
호출 프로그램의 후속 처리 예: 작업 초안 생성

처리 흐름은 메시지 수집 → 질문 구성 → Jev 판단 → 결과·불확실성 확인 → 프로그램의 작업 실행이다. 모델은 분류를 담당하고, 초안 생성 함수·저장 위치·승인 절차는 프로그램이 정의한다. 이 적용 방식은 공식 문서의 판단 결과를 코드로 연결하는 패턴에서 도출한 설계다. 공식 활용 흐름

5. LLM과 무엇이 다른가

TypeSafe는 사전학습 언어 모델을 정형 판단과 확률 보정에 맞춰 학습하는 RLCD(Reinforcement Learning for Calibrated Decisions)를 설명한다. “AI 모델 없이 JSON 규칙만 실행한다”거나 “언어 모델과 완전히 무관하다”는 해석은 맞지 않는다. 학습 방식에 관한 설명은 공급자 주장으로, 여기서 독립 검증한 것은 아니다. 공식 AI primer

일반 LLM에도 정형 출력을 요구할 수 있다. TypeSafe 역시 비교 실험용 LLM 어댑터를 공개한다. 차이는 JSON 사용 여부만이 아니라 정형 판단·확률 반환을 목표로 설계한 모델이라는 점이다. 성능 우위는 개별 업무 데이터로 검증해야 한다. 공식 출시 글

적용 해석: 메시지 분류·라우팅·우선순위 평가처럼 답의 범위를 미리 정할 수 있는 판단을 Jev에 맡기고, 설명문·코드 생성처럼 개방형 출력이 필요한 부분은 LLM에 맡기는 구성을 고려할 수 있다. 전체 에이전트 교체보다는 특정 판단 단계 교체에 해당한다.

6. 확률·confidence·정확성

probabilities는 후보별 확률이다. Choice와 Score의 confidence는 그 확률 분포가 얼마나 한쪽으로 집중되는지 요약한 수치다. 선택된 답의 확률과 같은 값으로 취급하거나, confidence 0.8을 곧바로 정답률 80%로 읽으면 안 된다. 공식 Confidence

확률 보정은 여러 예측을 모았을 때 예측 확률과 관측 결과가 대응하도록 하는 목표다. 개별 답의 정확성을 보증하지 않는다. 출력 타입이 맞아도 분류가 틀릴 수 있다. 공식 AI primer

우리 적용에서는 정답 데이터로 정확도·혼동표를 측정하고, 불확실한 결과를 사람 또는 다른 모델에 넘기는 기준을 정해야 한다. 임계값은 미리 보편값으로 확정하지 않는다. 공식 임계값 지침
