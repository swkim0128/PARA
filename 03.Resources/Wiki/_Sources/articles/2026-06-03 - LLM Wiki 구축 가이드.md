## 📚 LLM Wiki란 무엇인가?

**LLM Wiki** 는 안드레 카파시가 제안한 새로운 지식 관리 패턴입니다. 핵심 아이디어는 간단합니다:

**"AI가 지식을 읽고, 정리하고, 연결하고, 유지보수한다. 인간은 아이디어를 탐구하고 질문한다."**

기존의 지식 관리 방식은 인간이 직접 노트를 작성하고, 태그를 달고, 링크를 연결했습니다. 하지만 이 방식은 시간이 지날수록 **유지보수 부담이 기하급수적으로 늘어납니다**. 문서가 많아질수록:

- 어떤 문서끼리 연관되어 있는지 파악하기 어려워집니다
- 새로운 정보가 기존 정보와 모순되는지 확인하기 어렵습니다
- 오래된 정보가 최신 정보로 업데이트되지 않습니다
- 링크가 끊어지거나 중복된 문서가 생깁니다

LLM Wiki는 이 모든 **'지루한 유지보수 작업'을 AI에게 위임** 합니다. AI는 지루해하지 않고, 실수하지 않으며, 한 번에 수십 개의 파일을 수정할 수 있습니다.

**📝 안드레 카파시의 원문 핵심 요약** ([원문 보기](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f))

이 페이지는 Andrej Karpathy가 제안한 **LLM 기반 개인 지식 베이스 패턴** 을 설명하는 아이디어 노트입니다.

**핵심 아이디어:** 기존 RAG처럼 매 질문마다 원문에서 조각을 찾아 쓰는 대신, LLM이 **지속적으로 축적·갱신되는 마크다운 위키** 를 자동으로 작성·유지하는 구조를 제안합니다. 사용자는 자료를 모으고 방향을 정하는 데 집중하고, 요약·교차참조·정리 같은 **북키핑 작업은 전부 LLM이 담당** 합니다.

**주요 작업 플로우:**

- **Ingest**: 새 자료를 raw 폴더에 넣으면 LLM이 읽고 요약 페이지를 만들고, 관련 엔티티/개념 페이지를 10~15개 정도까지 갱신하며 로그에 기록합니다.
- **Query**: 질문은 위키를 대상으로 하고, LLM이 관련 페이지를 찾아 종합 답변을 주며, 좋은 답변은 다시 위키 페이지로 저장해 지식을 누적시킵니다.
- **Lint**: 모순, 오래된 주장, 연결이 끊긴 페이지, 아직 페이지가 없는 중요한 개념 등을 정기적으로 점검해 위키의 건강을 유지합니다.

**인덱스와 로그:** `index.md` 는 모든 위키 페이지를 카테고리별로 나열한 콘텐츠 인덱스이며, `log.md` 는 ingest·query·lint 이벤트를 시간 순으로 기록하는 변경 이력입니다.

**활용 팁:** Obsidian Web Clipper, 이미지 로컬 다운로드, 그래프 뷰, Marp 슬라이드, Dataview 플러그인 등을 활용해 **로컬 Obsidian+Git 기반 LLM 위키 IDE** 환경을 구성할 수 있습니다. 이 패턴은 개인 일지, 장기 리서치, 책 읽기 노트, 팀 내 위키, 경쟁 분석·실사 등 **장기간 누적되는 어떤 지식 작업에도 적용 가능** 한 일반 패턴입니다.

## 🔄 RAG vs LLM Wiki: 무엇이 다른가?

대부분의 LLM 기반 지식 시스템은 **RAG(Retrieval Augmented Generation)** 방식을 사용합니다. 하지만 RAG에는 근본적인 한계가 있습니다.

| 특징 | RAG | LLM Wiki |
| --- | --- | --- |
| **지식 처리 방식** | 질문 시마다 문서에서 검색 | 사전에 문서를 위키로 컴파일 |
| **지식 축적** | 없음 (매번 새로 검색) | 있음 (복리 효과) |
| **문서 간 연결** | 자동 생성 안 됨 | 자동 생성됨 |
| **모순 감지** | 질문 시에만 가능 | 지속적으로 감시 |
| **토큰 효율** | 질문마다 많은 토큰 필요 | 컴파일된 위키만 참조 |

RAG는 마치 **매번 도서관에서 책을 찾아 읽는 것** 과 같습니다. 반면 LLM Wiki는 **도서관 사서가 미리 중요한 내용을 요약해둔 노트를 참조하는 것** 과 같습니다. 질문할 때마다 원문을 다시 읽을 필요가 없죠.

## 🏗️ LLM Wiki 3계층 아키텍처

LLM Wiki는 세 개의 계층으로 구성됩니다:

### 📂 1계층: Raw Sources (원시 소스)

**수정하지 않는 원본 문서들** 입니다. 웹에서 클리핑한 글, PDF 논문, 회의록, 개인 노트 등이 여기에 저장됩니다. 이 폴더는 **'진실의 원천'** 역할을 하며, AI는 읽기만 하고 절대 수정하지 않습니다.

### 📝 2계층: Wiki (위키)

**AI가 생성하고 관리하는 마크다운 파일들** 입니다. 소스 요약, 엔티티(사람, 조직) 페이지, 개념 페이지, 비교 분석 문서 등이 포함됩니다. 이 계층은 AI가 완전히 소유합니다.

### 📋 3계층: Schema (스키마)

**AI에게 지시를 내리는 규칙 파일** 입니다. 문서를 어떻게 요약할지, 어떤 엔티티를 추출할지, 링크를 어떻게 연결할지 등을 정의합니다. 이 파일(CLAUDE.md)을 수정하면 AI의 동작 방식이 바뀝니다.

**💡 핵심 통찰**

이 아키텍처의 핵심은 **책임의 분리** 입니다. 인간은 소스를 큐레이션하고(1계층), AI는 위키를 유지보수하고(2계층), 스키마는 협업 규칙을 정의합니다(3계층). 각 계층이 독립적으로 작동하면서도 유기적으로 연결됩니다.

### 🌐 1단계: 폴더 구조 생성

Claude Code에게 다음과 같이 요청합니다:

```bash
Build me a complete LLM Wiki system based on this idea from Karpathy(https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f#llm-wiki). 
I use Obsidian. Create the folder structure, initial scripts/tools if needed, 
and give me clear step-by-step instructions on how to ingest data and have you maintain the wiki. 
Make it practical and ready to run today.
```

Claude Code가 자동으로 다음과 같은 폴더 구조를 생성합니다:

```glsl
LLM WIKI/
├── CLAUDE.md              # AI 지시서 (스키마)
├── README.md              # 사용 가이드
│
├── LLM WIKI/              # Obsidian 볼트
│   ├── .obsidian/         # Obsidian 설정
│   ├── Clippings/         # 웹 클리핑 저장소
│   └── *.md               # 기타 노트
│
├── wiki/                  # AI 관리 영역
│   ├── index.md           # 마스터 카탈로그
│   ├── log.md             # 활동 로그
│   ├── overview.md        # 종합 요약
│   ├── entities/          # 사람, 조직
│   ├── concepts/          # 개념, 이론
│   ├── sources/           # 소스 요약
│   └── analysis/          # 심층 분석
│
└── tools/                 # 유틸리티
    └── search.py          # 검색 도구
```

### 🔧 2단계: Obsidian Web Clipper 설치

[Obsidian Web Clipper](https://chromewebstore.google.com/detail/obsidian-web-clipper/cnjifjpddelmedmihgijeibhnjfabmlf) 를 설치하면 웹의 어떤 글이든 **클릭 한 번으로 마크다운으로 저장** 할 수 있습니다. 설정에서 **Clippings 폴더** 로 저장되도록 지정합니다.

설치 후 브라우저에서 원하는 글을 열고 클리퍼를 실행하면 자동으로 Clippings 폴더에 저장됩니다.

### 💬 3단계: 문서 수집 및 처리

새로운 문서가 Clippings 폴더에 저장되면, Claude Code에게 다음과 같이 요청합니다:

```actionscript
Ingest new clippings
```

그러면 Claude Code가:

1. 원본 문서를 읽고 핵심 내용을 파악합니다
2. 소스 요약 페이지를 생성합니다
3. 관련 엔티티(사람, 조직) 페이지를 생성하거나 업데이트합니다
4. 핵심 개념 페이지를 생성하거나 업데이트합니다
5. index.md를 갱신합니다
6. log.md에 활동을 기록합니다

## 🌐 웹 인터페이스 제작

LLM Wiki는 Obsidian에서 직접 사용할 수도 있지만, **위키백과 스타일의 웹 인터페이스** 를 만들면 더욱 편리합니다.

### 📊 웹 인터페이스 기능

| 기능 | 설명 |
| --- | --- |
| **문서 보기** | 위키백과 스타일로 문서 표시 |
| **전체 검색** | 모든 위키 내용 검색 |
| **지식 그래프** | 문서 간 연결 관계 시각화 |
| **백링크** | 해당 문서를 참조하는 다른 문서 표시 |
| **무작위 문서** | 랜덤 문서로 이동 |

### ⚙️ 실행 방법

다음 명령어로 로컬 웹 서버를 실행합니다:

```tcl
cd "LLM WIKI/web"
python -m http.server 8000
```

브라우저에서 **http://localhost:8000** 에 접속하면 위키백과 스타일의 인터페이스를 볼 수 있습니다.

### 🔍 질문하기

위키에 축적된 지식을 바탕으로 질문할 수 있습니다:

```julia
What do I know about [topic]?
```

Claude Code가 위키를 검색하고, 관련 문서들을 종합하여 답변합니다. 답변에는 위키 링크가 포함되어 출처를 바로 확인할 수 있습니다.

### 🔧 위키 건강 검진

주기적으로 위키를 검진하면 더욱 풍부한 지식 베이스가 됩니다:

```bash
Lint the wiki
```

이 명령을 실행하면 Claude Code가 다음을 점검합니다:

- **모순**: 서로 다른 문서에서 상충하는 정보
- **고아 문서**: 링크가 없는 문서
- **누락된 문서**: 링크는 있으나 생성되지 않은 문서
- **오래된 정보**: 최근 소스에서 반박된 주장
- **데이터 갭**: 제기되었으나 답변되지 않은 질문

LLM WIKI Lint 작업

**⚠️ 주의사항**

LLM Wiki의 진정한 가치는 **시간이 지날수록 발휘** 됩니다. 처음에는 몇 개의 문서만 있지만, 꾸준히 소스를 추가하고 린트를 실행하면 지식이 기하급수적으로 풍부해집니다. 이 과정에서 AI가 스스로 패턴을 발견하고, 예상치 못한 연결을 만들어내며, 지식의 '복리 효과'를 경험하게 됩니다.

## 🎯 맺음말

지금까지 안드레 카파시의 **LLM Wiki 패턴** 을 활용해 **Claude Code와 Obsidian으로 스스로 진화하는 개인 지식 베이스를 구축** 하는 방법을 알아보았습니다. LLM Wiki는 AI가 지식을 자동으로 정리, 연결, 유지보수하는 시스템으로, RAG와 달리 지식이 시간이 지날수록 풍부해지는 **복리 효과** 를 제공합니다.

핵심 요약:

- **LLM Wiki** 는 AI가 지식을 자동으로 정리, 연결, 유지보수하는 시스템입니다
- **RAG와 달리** 지식이 시간이 지날수록 풍부해지는 복리 효과가 있습니다
- **3계층 아키텍처** (Raw Sources → Wiki → Schema)로 명확한 책임 분리가 가능합니다
- **웹 인터페이스** 를 통해 위키백과 스타일로 지식을 탐색할 수 있습니다

LLM Wiki는 단순한 노트 정리 도구가 아닌, AI 시대의 **새로운 지식 관리 패러다임** 입니다. 여러분도 한번 Claude Code로 LLM Wiki를 직접 구축해보시길 추천드리면서 저는 다음 시간에 더 유익한 정보를 가지고 다시 찾아뵙겠습니다. 감사합니다.
