# RAG vs LLM Wiki

LLM 기반 지식 시스템의 두 패러다임 비교. 원천 출처: [[Andrej Karpathy]] gist (해설: [[2026-06-03 - LLM Wiki 구축 가이드]]).

## 비교 매트릭스

| 특징 | [[RAG]] | [[LLM Wiki]] |
|---|---|---|
| **지식 처리 방식** | 질문 시마다 문서에서 검색 | 사전에 문서를 위키로 컴파일 |
| **지식 축적** | 없음 (매번 새로 검색) | 있음 ([[지식의 복리 효과]]) |
| **문서 간 연결** | 자동 생성 안 됨 | 자동 생성 (wikilink) |
| **모순 감지** | 질문 시에만 가능 | 지속적 감시 (Lint) |
| **토큰 효율** | 질문마다 많은 토큰 필요 | 컴파일된 위키만 참조 |
| **유지보수 주체** | 운영자 (벡터 DB·임베딩) | LLM 자체 (스키마 기반) |
| **초기 구축 비용** | 낮음 (인덱싱만) | 중간 (스키마 정의·첫 ingest) |
| **장기 운영 가치** | 일정 (변동 없음) | 증가 (누적 효과) |

## 비유

| | RAG | LLM Wiki |
|---|---|---|
| 비유 | 매번 도서관에서 책을 찾아 읽는 행위 | 사서가 미리 요약해둔 노트 참조 |
| 강점 | 즉시성, 임의 코퍼스 대응 | 누적 가치, 교차 참조 |
| 약점 | 매번 0에서 출발 | 초기 셋업, 스키마 설계 부담 |

## 선택 기준

- **RAG 적합**: 대규모·동적 코퍼스, 실시간 변경, 코퍼스 자체가 진실의 원천 (예: 사내 SaaS 문서 검색).
- **LLM Wiki 적합**: 장기 누적 지식, 개인·소수 협업, 합성·교차 참조가 핵심 가치 (예: 개인 리서치 노트, 책 읽기 메모, 경쟁 분석).

## 결론

두 패턴은 **상호 배타가 아님**. RAG 위에 LLM Wiki 레이어를 얹어 합성 결과만 검색 인덱스에 포함시키는 하이브리드도 가능. 본 볼트는 **개인 지식 누적이 1차 목적**이므로 LLM Wiki를 기본 채택.
